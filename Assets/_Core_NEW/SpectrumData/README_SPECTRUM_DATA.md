# Spectrum Data — Guide

Physically modelled spectrum of the quasar's light for the whole journey, **precomputed in the Editor** and played back at runtime.

> **Switch:** `BakedSpectrumSource_NEW.useBakedData`. Off (or component not in the scene) = nothing loads, nothing is overridden, the old procedural forest runs exactly as before.

Also in this folder:
- `SOURCES.md`: every number and its confidence
- `OPEN_QUESTIONS.md`: what the data says about the script, for the team meeting

---

## 1. Why it's built this way

A previous spectrum-data path read data in the background every frame and cost frame rate. This one is designed so that cannot happen:

| Rule | How |
|---|---|
| **No heavy work at runtime** | All physics runs once, in the Editor, into a 1.5 MB file |
| **Load once** | One 1 ms parse at `Start`. No file I/O, parsing or `Resources.Load` after that |
| **Tiny per-frame cost** | ~9 µs, and only when the journey has moved far enough to change the picture. Most frames do nothing |
| **No allocation per frame** | All buffers created once |
| **Isolated** | Existing components expose hooks and **never reference this folder**. Switch it off, or delete the folder, and nothing else breaks |
| **Fail safe** | A missing or corrupt file logs one error and switches the feature off |

Measured numbers are printed by the command-line check (§6).

## 3. How it works

### The axis

The journey bar is a **log-wavelength axis from 1216 Å to 9,000 Å** (`lambda_min_A` auto, `lambda_max_A` 9000 in `bake_settings.csv`), covering UV, visible and near-IR so the tutorial bands map onto the same bar. The left edge is the birth tick. The HUD draws the quasar's own spectrum, so the right side always has shape, and no part of the bar is ever empty. Redshift multiplies every wavelength by the same factor, and on a log axis that is a uniform shift. The whole spectrum slides as one piece and every line keeps its shape.

| On the bar | Wavelength | Position |
|---|---|---|
| **Birth tick**: where every Lyα line is born | 1216 Å | 0 (left edge) |
| Visible light begins | 4000 Å | 0.78 |
| Quasar's Lyα peak at emission | 1216 Å | 0 (left edge) |
| Quasar's Lyα peak at Earth | ~5610 Å (visible) | 0.94, red side still showing |

### The bake (`SpectrumModel_NEW`)

The light is followed in 384 steps, each an equal amount of stretch. Each step:

1. **Stretch.** Shift everything redward by exactly 4 grid cells. It's an integer shift, so nothing blurs.
2. **Hydrogen.** Imprint the gas crossed during this step at the fixed 1216 Å cells (Lyα) and 1026 Å cells (Lyβ). Absorption strength is calibrated so the mean matches `mean_flux.csv` at every z. It is reduced near the quasar (proximity zone).
3. **Ionisation.** Absorb everything below 912 Å locally, at the rate set by `mean_free_path.csv`.
4. **Helium.** Absorb everything below 228 Å locally until z = 3.
5. **Read out** one row: the emitted template, stretched, times the accumulated transmission.

Output: a 1024 × 384 grid of flux (for the HUD) and absorption (for the trail), a z(lookback) table, and a list of notable absorbers.

### At runtime (`BakedSpectrumSource_NEW`)

```
UniverseJourneyTracker.RemainingDistanceLy  (ly still to travel)
      ÷ 1e9  → lookback time, Gyr
      → z                       (baked table)
      → row                     (0 = emission, 383 = Earth)
      → blend two rows          → HUD curve, trail absorption, mark positions
```

Remaining light-years of light-travel distance **is** lookback time in years, so the spectrum follows the tracker with no extra mapping.

### What it drives

| Target | Hook it calls | Effect |
|---|---|---|
| `SpectrumHUD_NEW` | `SetExternalCurve` | Draws the baked row instead of template × random lines, and stops its own drift. **Default (`hudDisplay = Flux`): the quasar's own spectrum with only the Lyα forest cut into it.** The peak starts at the left edge and walks right with redshift, emission-line shape to its right and the forest growing to its left. `Transmission` shows absorption alone, with no quasar shape. The light is treated as constant and only absorption is shown, so a wavelength the quasar simply emitted less of never looks absorbed. `Flux` shows the physical spectrum, for checking against observations |
| `AbsorptionField_NEW` | `SetExternalAbsorption` | Trail shows baked absorption. Stops spawning and drifting, and **uploads its texture only when the row changes** (the procedural path uploads every frame) |
| `RedshiftMarks_NEW` | `SetPhysicalMarks`, `SetPhysicalMapping`, `SetPhysicalReplay` | **Marks come from the data; no manual setup.** [0] is the first line the light acquired (the tutorial's line). The rest are the strongest absorber in each equal-stretch redshift slice down to z = 0.9, i.e. the densest gas crossed in that slice, all present by the second cosmic web. **One shared anchor**: the birth tick, 1216 Å, since all hydrogen absorbs there locally. **`Spread()` replays the real history** instead of multiplying distances: the baked physics runs from the quasar to now over `spreadSeconds`, with lines born at the anchor and stretched to where they really are. The serialized mark list is only used by the procedural fallback and the editor preview |

Each can be turned off individually (`driveHud`, `driveTrail`, `driveMarks`).

## 4. Scene setup (Gameplay_Scene_Ana)

1. Add `BakedSpectrumSource_NEW` to the systems root
2. Drag `Baked/SpectrumJourney.bytes` into **Baked File**
3. HUD, field, marks and tracker are auto-found. Assign them if there are several
4. Nothing to fill: the marks are taken from the data every time it loads, so they can never point at an old bake
5. Play. The Console shows `Loaded 'SpectrumJourney' in … ms`

`RedshiftBudget_NEW` still works, but only affects the fallback. With baked data on, the HUD doesn't drift on its own.

**Debug keys (Play mode):** F9 plays the arrival zoom. F10 replays the light's history, which is what the demo's Spread step does.

**Inspect any point of the journey without flying there:** set `overrideLookbackGyr` (12.07 = emission, 7 ≈ second cosmic web, 0 = Earth).

## 4b. The arrival: zoom into the reference figure

At Earth the bar zooms **continuously** from the whole barcode into the classic Lyman-α forest figure (Q1422+2309: intensity vs **emitted** wavelength, 1000–1350 Å). It then lets the quasar's own spectrum rise in: the Lyα peak with the forest to its left.

- **Both edges move.** The bar (1216–9,000 Å) narrows onto the reference window; the right edge comes in from 9,000 to 6,231 Å.
- **It is a zoom, not a cut.** At Earth the light's current wavelength *is* the observed wavelength, so the same curve is shown over a narrower range. "Emitted 1000–1350 Å" is observed 4,616–6,231 Å.
- **Sequence:** enter layer `arrivalLayerId` (Earth) → wait `arrivalDelaySeconds` (4) → **zoom** `zoomSeconds` (5), still absorption-only → **reveal** `revealSeconds` (3), blending into the real spectrum → `onArrivalComplete`.
- **Data:** the bake reads out a separate high-resolution arrival frame (16,384 samples, ~30 km/s) covering both the bar and the reference window. It is not an upscaled journey row.
- **Check it:** `Baked/SpectrumJourney_arrival.png` is that final frame drawn like the reference. The bake report prints the forest-to-continuum level: **0.646** (measured composite), against ~0.7 for Q1422.
- **Resolution on screen:** the HUD resamples to its `sampleCount` (512). 1024 and a thicker line were tried and looked worse; 512 / 0.1 is the chosen setting.
- **Switch / manual:** `arrivalEnabled`. `PlayArrival()` can be called from a sequence step instead. **F9** plays it immediately (debug).

## 4c. The tutorial: the same data, the first 1.5% of the trip

The tutorial bar is drawn from the **same baked file** as the journey. It plays the start of the real journey, time-compressed, and the journey carries on from exactly where it stopped. Across the black, the bar is the same frame.

**Setup (tutorial scene, once).**
1. Add `TutorialBakedSpectrum_NEW` to any object in the tutorial scene, for example next to `TutorialSpectrum_NEW`.
2. Drag `Baked/SpectrumJourney.bytes` into **Baked File**. The rest of the wiring is found in the scene; assign **Spectrum Trail** by hand if the scene has more than one `PhotonSpectrumTrail`.
3. Save the scene. Nothing is needed in the journey scene: `BakedSpectrumSource_NEW` picks the handoff up by itself.

**Kill switch:** `useBakedData`. Off, even while playing, releases every override, and the tutorial's authored spectrum runs exactly as before.

**What happens, beat by beat.**

| Beat | Bar | Data |
|---|---|---|
| D3 | Appears on the **full** 1216–9000 Å bar, with UV / visible / IR at their real edges (4000 Å, 7000 Å). The clock starts. | z = 3.62, the moment of emission |
| D4 | **Zooms ~17×** onto 1202–1350 Å, beside the birth tick. All of it is UV. | Real drift is ~1 px per atom on the full bar; ~20 px here |
| D5 / D6 / D8 | Each atom cuts a **real line**: the strongest absorber in the cells the light has just crossed, at its real depth. Until D9 only these lines are shown. | 1 + 3 + 1 atoms, at 2.4 s spacing in D6 |
| D9 | **Zooms back out** to the full bar, and the **rest of the forest fades in**. That is all the gas the atoms stood for. | |
| End | The journey opens on this exact frame. It holds there until the tracker catches up (~2 s), then flies on at its own pace. Mark [0], "the first line", is the player's own D5 line. | ~0.18 Gyr travelled, z ≈ 3.32 |

**Time compression.** `gyrPerSecond` = 0.003, so Phase 3's ~60 s cover ~0.18 Gyr, about 1.5% of the journey (capped at `maxSpanGyr` = 2%). Real light takes 0.18 Gyr to do this. The journey's own pace is ~30× faster than the tutorial's.

**Trail.** By default (`trailAxis = AllBands`) the ribbon always shows UV, visible and IR on a fixed piecewise axis, like a broken axis. 1000–1202 Å takes 20%: real UV with no lines, there to keep the lines clear of the ribbon's outer edge, where the shader fades everything out, black lines included. 1202–1400 Å, where the tutorial's lines live, takes 25%, so lines sit at about 22–34%. The rest of the UV takes 10%, visible 30% and IR 15%. UV is drawn at `uvAlpha` 0.65, so the black lines have something bright behind them. The bar zooms independently, and the bar arrow and the trail arrow each use their own axis. `FollowBar` puts the ribbon on the bar's exact axis instead, zoom included, so it is all UV while zoomed. Its colours are real wavelengths: UV below 4000 Å, the rainbow 4000–7000 Å, IR above. The band edges are pushed into `PhotonSpectrumTrail.uvBandWidth / irBandWidth`, which the tutorial's band overlays already read. The colour texture is replaced through a MaterialPropertyBlock, so the shared material is untouched.

**Checked offline (2026-10-04):** a replay of the beat timeline with these constants gave separate lines for every atom and an end frame within 0.0035 (mean) of the journey's own row. `Tools~/BakeCheck` re-checks the data side on every bake.

**File format 4** adds what this needs: the **path record** and the **intrinsic spectrum**. The path record is the Lyα transmission each 37 km/s cell of gas imprinted, 12,256 cells, 24 KB. Lyα touches a photon only once, so this one array *is* every row of the journey grid. `SampleView` draws any moment on any axis from it, and the harness checks it reproduces the grid to within 1%. The intrinsic spectrum is the quasar's emitted spectrum, 8,192 samples. Format 3 files still load in the journey, but the tutorial needs format 4.

## 4d. Gameplay line highlight (`AbsorberHighlight_NEW`)

The tutorial's "this gas = this line" moment, used **only while the piece explains redshift**: the demo's steps call it. The line blinks on the bar and on the trail, then an arrow under the bar and an arrow at the ribbon follow it for the step.

**No wiring needed.** `JourneySequence_NEW` announces each step (`OnStepEntered`), and on the steps listed in `firstLineSteps` (default **F3, F4**) the highlight shows the **first line**, the player's own, for that step's duration:
- the line blinks on the bar and the trail, with arrows;
- an **anchor** marks the birth tick, where it was born;
- a **bracket** under the bar runs from the anchor to the line: how far it has travelled.

In F4 (`Spread`) it follows the line through the replay, from its birth to where it is now. `HighlightFirstLine`, `HighlightMark(i)` and `StopHighlight` are also public, for other steps.

`autoOnCrossings` (off by default) restores the automatic version: a highlight whenever the flying light crosses a marked absorber.

- **Automatic mode only — trigger: the data, not scenery.** The marked absorbers are the bake's notable absorbers, the same list `RedshiftMarks_NEW` uses; [0] is the player's own tutorial line. The gameplay scene has no hydrogen-cloud objects. If one is added later, it can call `HighlightNow()` on entry.
- **Automatic mode only — frequency:** about 8 over the trip, a few seconds apart. The first comes as soon as the hold after the tutorial ends: absorber [1] at z 3.31 sits right at the tutorial's end point. A crossing within `minSecondsBetween` (4 s) of the last highlight is skipped.
- **Suppressed:** while the bar holds after the tutorial, during the redshift demo's replay, and during the arrival.
- **Only that line blinks on the trail.** `BakedSpectrumSource_NEW.SetTrailEmphasis` cuts just that line solid, so the rest of the forest stays still.

**Setup:** add `AbsorberHighlight_NEW` to any object in Gameplay_Scene_Ana. The rest is found in the scene. The graphics are created at runtime under the `RedshiftMarks_NEW` object and the root canvas. **Kill switch:** `highlightEnabled`. **F12** highlights the line being born now. If the trail arrow points at the wrong edge of the ribbon, tick `flipAcross`.

**Pacing: `NarrationSlowdown_NEW`.** The explanation (J5, then F1–F6) runs about a minute, but the second cosmic web takes about 22 s at normal speed. The VO only starts the demo if J5 ends while the player is still in that layer, so at full speed the demo never started.
- **Slows down:** on entering `CosmicWeb`, the flight eases to 0.3×, so the layer lasts about 70 s.
- **Back to normal:** when the demo finishes, when the layer is left, or after 90 s.
- **Separate multiplier:** it uses `PlayerRig_NEW.SetNarrationSpeedMultiplier`, which is separate from the per-layer multiplier `SpeedResponder_NEW` drives, so the two never fight.
- **Setup:** add it to any object in the gameplay scene. **Kill switch:** `slowdownEnabled`.

**The journey trail now uses real wavelengths too** (`BakedSpectrumSource_NEW.trailRealWavelengths`, on by default). Without that, a just-born line sits on the ribbon's outer edge, where the shader fades it to nothing, and under a colour that is not its wavelength. It works the same way as in the tutorial:
- a far-UV margin of 20% on the outer side;
- then the bar's axis, coloured UV below 4000 Å, the rainbow 4000–7000 Å, IR above.

Untick it to keep the trail's original art colours; lines then go back to the outer edge.

## 5. Changing things

| To change… | Do |
|---|---|
| Any physical number | Edit the CSV in `Tables/` → **Tools › Journey NEW › Spectrum Data › Bake Journey Spectrum** |
| The journey's starting distance | Update `lookback_start_gyr` in `bake_settings.csv` to match the tracker, re-bake |
| The axis range or resolution | `bake_settings.csv` (`lambda_min_A`, `lambda_max_A`, `columns`, `rows`), re-bake |
| The forest's random pattern | `random_seed`, re-bake. Same seed = same forest |
| Turn it off | Untick `useBakedData`. Works during play |

**After every bake:**
- Open `Baked/SpectrumJourney_report.txt` and check the **CALIBRATION** table
- Look at `SpectrumJourney_preview.png`

**Reading the preview image:** top row = emission, bottom = Earth, left→right = wavelength.

Brightness is **transmission**: white = nothing absorbed, black = absorbed. The same thing the HUD draws.

| Colour | Meaning |
|---|---|
| Blue vertical | 1216 Å birth tick |
| Red diagonal | the quasar's own Lyα peak walking into the infrared |
| Green verticals | edges of visible light |
| Yellow row | the freeze: no new lines below it (see `OPEN_QUESTIONS.md`) |

**Changing the file format:** bump `BakedSpectrumData_NEW.FormatVersion` (now 2; version 2 added the arrival frame). Old files are then refused with "re-bake" instead of misread.

## 6. Checking a bake without Unity

```
cd Assets/_Core_NEW/SpectrumData/Tools~/BakeCheck
dotnet run -c Release
```

This runs the **same model files** the Unity baker uses, then checks the result:

- round-trips it through the runtime reader
- checks the z ↔ lookback ↔ row mappings and the axis
- confirms bad files are rejected
- times the per-frame cost

It writes `out/` (bytes, preview, report) and exits 0 if every check passes. It compiles as C# 7.3, Unity 2019.4's language version, so anything that builds here builds in Unity.

Needs the .NET SDK. Unity does not.
